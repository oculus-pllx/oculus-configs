# Architecture Decision Log

Records major architectural decisions, their reasoning, and current status.
Reference these when designing new features or considering refactors.

---

## ADR Template

```
## ADR-XXX: [Decision Title]
**Date**: YYYY-MM-DD
**Status**: Proposed | Accepted | Deprecated | Superseded

**Context**: [Why did we need to make this decision?]

**Decision**: [What we decided]

**Rationale**:
- Reason 1
- Reason 2

**Alternatives Considered**:
- Alternative A: [why rejected]

**Consequences**:
- Pro: [benefit]
- Con: [tradeoff]
```

---

## When to Add an ADR

Add one when:
- Choosing a framework, database, or critical library
- Making an architectural pattern decision
- Deciding between competing implementation approaches

Skip for:
- Bug fixes
- Feature-specific implementation details
- One-off workarounds
