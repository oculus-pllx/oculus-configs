## claude/CLAUDE.md
### When a request turns out to span multiple systems or components, decompose it into ordered, dependent sub-projects with an explicit build order before writing an implementation plan.
- **Why:** Prevented conflating three separate multi-system efforts (provider-selection, selective-publish, dashboard) into one unmanageable plan; this is a general planning discipline not addressed by existing plan-before-execute or writing-plans guidance.
- **Citations:** 69990b5e-b735-4df3-8c34-e67e5ff77a98 turn 72
- **Suggested placement:** Workflow Standards section

### When a new design/spec supersedes an older one, mark the old doc as superseded rather than deleting it.
- **Why:** Preserves decision history while keeping the current source of truth unambiguous; complements but is not covered by the existing DECISIONS.md rule, which addresses tracking architecture decisions but not doc lifecycle/versioning.
- **Citations:** 6a63e5ed-c692-4d25-88a5-4ab99a4cdea4 turn 88
- **Suggested placement:** Workflow Standards section, near the DECISIONS.md rule

### If the user doesn't respond to a clarifying question within a reasonable time, proceed with best judgment and explicitly flag the assumption for later confirmation rather than blocking.
- **Why:** Kept a session moving toward a usable design instead of stalling indefinitely on an unanswered question, while still surfacing the unilateral decision for review — a general unblocking pattern not present in current config.
- **Citations:** 8707f166-d9b2-478d-a3c1-f33ad0ac5d17 turn 38
- **Suggested placement:** Workflow Standards section

### When pushing to main and the remote has diverged, rebase onto the remote before pushing rather than force-pushing or merging; if push fails for other reasons (e.g. no remote), keep the local commit and flag the issue to the user instead of blocking.
- **Why:** Kept a linear history consistent with the no-PR, main-only workflow, and avoided losing committed work when a remote wasn't configured — a concrete git mechanic not spelled out by the existing 'commit and push to main' rule.
- **Citations:** aafcb079-9cdb-4f2c-8af8-e884d46ac9e8 turn 118, 6a63e5ed-c692-4d25-88a5-4ab99a4cdea4 turn 91
- **Suggested placement:** Workflow Standards section, near 'Commit frequently'

## claude/rules/code-quality.md
### When a generated artifact contains machine-local sensitive details (IPs, deploy paths, credentials), leave it uncommitted by default and flag the tradeoff to the user instead of committing automatically.
- **Why:** Avoided leaking a deployment box's IP into git history while still delivering the requested report; goes beyond the existing 'no hardcoded secrets' pre-commit check, which only covers code, not generated docs/reports.
- **Citations:** 2ee5ac69-a4d2-4ed8-9e69-20c924b352dd turn 64
- **Suggested placement:** Pre-Commit Checks section

### If a commit is blocked by .gitignore, inspect the .gitignore and tracked-file history (git ls-files/log) to understand the intentional reason before deciding whether to force-add.
- **Why:** Caught that a docs/specs path was deliberately untracked because the repo is public, preventing an accidental force-commit of internal docs to a public repo — a specific safeguard not covered by existing pre-commit checks.
- **Citations:** 774538ff-d050-41ee-b896-f3f64f6141bf turn 103
- **Suggested placement:** Pre-Commit Checks section

### Before refactoring or editing a feature, grep the codebase for every reference to it (routes, services, tests, UI) to map all touchpoints first.
- **Why:** Prevented missed call sites when refactoring an install flow by surfacing routes, services, tests, and UI components together up front; a general code-navigation discipline not in the current code-style rules.
- **Citations:** aafcb079-9cdb-4f2c-8af8-e884d46ac9e8 turn 8
- **Suggested placement:** Code Style section

### Run the full existing test suite once at the start of a task to record a pre-existing failure baseline, and cross-check any later failures against it before treating them as regressions.
- **Why:** Let the assistant correctly attribute a pre-existing unrelated jest failure instead of misreporting it as caused by the current change — distinct from the existing 'all tests pass before committing' check, which only covers the end state.
- **Citations:** aafcb079-9cdb-4f2c-8af8-e884d46ac9e8 turn 60, aafcb079-9cdb-4f2c-8af8-e884d46ac9e8 turn 108
- **Suggested placement:** Pre-Commit Checks section

### If a credential-bearing file is discovered already committed to the repo, immediately untrack it (git rm --cached) and add it to .gitignore as part of the fix, not just a flagged finding.
- **Why:** Directly remediated a plaintext root password committed to GitHub in HANDOFF.md; extends the existing 'no hardcoded secrets' rule (which is prevention-only) to cover remediation of already-committed secrets.
- **Citations:** aafcb079-9cdb-4f2c-8af8-e884d46ac9e8 turn 101
- **Suggested placement:** Pre-Commit Checks section

## claude/rules/grounding.md

- **Why:** Recurs across nearly every session as the difference between a speculative answer and a correct, citable one (e.g. grepping specs for pipeline scope, reading llm.py for auth design, reading HANDOFF.md for deploy blockers). Not covered by any existing rule, which only mandates process skills (brainstorming/TDD/review), not this evidence-gathering habit.

## claude/rules/plugin-usage.md
### During brainstorming/design for a feature touching existing code, audit for half-built functionality (data stored but never rendered/wired) and fold fixing it into the design scope rather than leaving it as a separate follow-up.
- **Why:** Surfaced that headers/redirects/access-log were stored in DB but never exposed in UI or Caddy config, turning a hidden gap into explicit user-approved scope instead of a missed issue.
